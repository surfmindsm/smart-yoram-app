# Church Round 모바일 앱 — 디자인 정책 (C 방향)

> Smart Yoram App 모바일 UI 통일 가이드.
> 목적: 화면마다 제각각이던 블루 계열·아이콘·여백을 **단일 스카이 액센트 + 슬레이트 중립색 + 라인 아이콘** 체계로 통일한다.
> 이 문서는 `*.dc.html` 목업과 짝을 이루며, 구현(Flutter) 시 **시각만 바꾸고 동작/데이터 흐름은 유지**하는 것을 원칙으로 한다.

---

## 1. 핵심 원칙 (Before → After)

| # | 원칙 | Before (현재) | After (C 방향) |
|---|------|---------------|----------------|
| 1 | **단일 액센트** | 화면마다 다른 블루 (`#0078FF`, `#4A90E2`) | 스카이 단일 액센트 `#0EA5E0` / 진한 `#0284C7` |
| 2 | **라인 아이콘** | 채움/혼용 아이콘 | Lucide 라인 아이콘 (stroke 2), 입력필드 좌측 아이콘 |
| 3 | **슬레이트 중립색** | 임의의 회색 (`#999`, `#6B7280`) | 슬레이트 스케일(`#0F172A`~`#CBD5E1`)로 통일 |
| 4 | **명확한 위계** | 화살표·구분선·카운트 부재 | 행 구분선 · `chevron-right` · 카운트/상태 배지 추가 |
| 5 | **여백과 라운드** | 평이한 간격 | 넉넉한 패딩 · 일관된 라운드(11~16px) · 부드러운 섀도 |

## 2. 디자인 토큰

### 2.1 컬러

```
// 액센트 (Primary = Sky)
sky/primary      #0EA5E0   주 버튼, 활성 아이콘/탭, 토글 ON, 포커스 링
sky/deep         #0284C7   강조 텍스트, 선택 칩 텍스트, 아이콘
sky/tint         #E0F2FE   아이콘 타일 배경, 칩/배지 배경
sky/wash         #F0F9FF   인포 박스 배경

// 중립 (Slate)
text/strong      #0F172A   제목·본문 강조
text/body        #1E293B
text/secondary   #475569   보조 텍스트, 메뉴 라벨
text/muted       #64748B   설명문
text/tertiary    #94A3B8   플레이스홀더, 부가정보, 섹션 헤더
icon/faint       #CBD5E1   chevron, 비활성 아이콘
border/strong    #E2E8F0   입력 테두리
border/soft      #F1F5F9   카드 구분
border/hair      #F4F7FA   리스트 행 구분
surface          #FFFFFF
canvas           #EEF2F6 / #F1F5F9   화면 배경

// 상태 (Status)
danger           #E11D48   로그아웃, 신고 / bg #FFE4E6, border #FECDD3
warning          #D97706 (#B45309)  예약중 / bg #FEF3C7
success          #059669   거래확정 / bg #D1FAE5
```

> **Flutter 적용 팁:** `lib/resource/color_style_new.dart`의 `NewAppColor.primary*` 계열을 위 sky 값으로 재정의하면 대부분의 화면이 자동으로 따라온다. 현재 `primary600 ≈ #0078FF`를 `#0EA5E0`로 교체하는 것이 1차 작업.

### 2.2 타이포그래피 (Pretendard)

| 역할 | 크기 / 굵기 | 비고 |
|------|------------|------|
| 화면 타이틀(앱바) | 18px / 800 | `letter-spacing:-.01em` |
| 큰 제목 | 22–23px / 800 | 온보딩·상세 |
| 카드/행 제목 | 15–16px / 700 | |
| 본문 | 14–15px / 500–600 | line-height 1.5–1.7 |
| 보조/설명 | 12–13px / 500 | `text/muted`·`tertiary` |
| 섹션 헤더 | 12px / 700 | `text/tertiary`, letter-spacing .03em |
| 배지/칩 | 11–12px / 700–800 | |

> 모바일 최소 가독 크기 12px. 본문은 14px 이상 유지.

### 2.3 스페이싱 · 라운드 · 섀도

```
라운드   입력 11px · 버튼 12–14px · 아이콘 타일 11px · 카드 16px · 바텀시트 26px(상단) · 원형 아바타 50%
패딩     화면 좌우 18px · 리스트 행 15px×18px · 카드 내부 16–22px
섀도     주 버튼  0 8–10px 20–22px rgba(14,165,224,.32)
         플로팅   0 10px 24px rgba(14,165,224,.42)
         바텀시트 0 -16px 40px rgba(2,8,23,.25)
포커스링 0 0 0 4px rgba(14,165,224,.12)  (+ 테두리 1.5px #0EA5E0)
```

### 2.4 아이콘
- **Lucide** 라인 아이콘, stroke-width 2.
- 크기: 본문 18–22px · 탭바 21px · 타일 안 18–23px.
- 입력필드는 좌측에 의미 아이콘(`mail`, `lock`, `phone` 등).

## 3. 컴포넌트 규격

| 컴포넌트 | 규격 |
|----------|------|
| **주 버튼** | 배경 `#0EA5E0`, 흰 텍스트 15px/800, 라운드 13–14px, 섀도(위 참고) |
| **보조 버튼** | 흰 배경 + `1.5px #BAE6FD` 테두리, 텍스트 `#0284C7` |
| **고스트/취소** | 배경 `#F1F5F9`, 텍스트 `#64748B` |
| **위험 버튼** | 배경 `#E11D48`(채움) 또는 `1px #FECDD3` 테두리 + 텍스트 `#E11D48` |
| **입력필드** | 테두리 `1px #E2E8F0`, 라운드 11px, 좌측 아이콘, 포커스 시 `1.5px #0EA5E0` + 4px 링 |
| **리스트 행** | 좌측 아이콘 타일(36–38px, 라운드 11px, `#E0F2FE`/`#0284C7`) + 라벨 + 우측 `chevron-right`(`#CBD5E1`) |
| **상태 배지** | 판매중=sky, 예약중=amber, 거래완료=gray. 11–12px/800, 라운드 7px |
| **카운트 칩** | `#E0F2FE`/`#0284C7`, 라운드 999px |
| **토글** | 트랙 46×28, ON `#0EA5E0` / OFF `#E2E8F0`, 노브 22px 흰색 |
| **세그먼트 토글** | 트랙 `#F1F5F9`, 선택 탭 흰 배경 + 섀도 + `#0284C7` 텍스트 |
| **카드 섬네일(이미지 없음)** | `repeating-linear-gradient(135deg,#EAF2F8 0 8px,#DEEAF3 8px 16px)` + 중앙 `image` 아이콘 (플레이스홀더) |
| **상단바** | 높이 56, 좌측 `chevron-left`, 가운데/좌측 타이틀 18px/800, 우측 액션 |
| **하단 탭** | 활성 `#0EA5E0`+700, 비활성 `#94A3B8`. 라벨 10px |
| **바텀시트/다이얼로그** | 흰 배경, 상단 라운드 26px(시트)/22px(다이얼로그), 핸들바 44×5, 어두운 배경 `rgba(15,23,42,.45)` |

## 5. 클로드 코드(개발 에이전트)에 전달하는 법

### 5.1 원칙
1. **시각만 변경, 동작 불변**: 위젯 트리/상태/API 호출은 그대로 두고 스타일 속성만 교체.
2. **토큰 우선**: 하드코딩 hex 대신 `NewAppColor`/`FigmaTextStyles` 상수를 쓰고, 없으면 §2 값으로 추가.
3. **목업이 정답**: 같은 폴더의 `*.dc.html`을 시각 기준으로 삼는다.
4. **1차 작업은 토큰 교체**: primary 블루 → 스카이로 바꾸면 전역이 따라온다.

### 5.2 붙여넣어 쓰는 프롬프트 템플릿

```
[작업] {화면명} 을 디자인 정책(C 방향)에 맞춰 리스타일링.

- 소스 파일: lib/screens/{파일명}.dart
- 디자인 기준: {파일명}.dc.html (개선안 프레임)
- 정책 문서: DESIGN_POLICY.md (§2 토큰, §3 컴포넌트 규격)

[해야 할 것]
1. 액센트 색을 스카이(#0EA5E0 / 진한 #0284C7 / 타일 #E0F2FE)로 교체.
2. 아이콘은 Lucide 라인, 입력필드 좌측 아이콘 적용.
3. 텍스트/회색은 §2.1 슬레이트 스케일로 매핑.
4. 리스트 행에 구분선 + chevron-right + 카운트/상태 배지(§3) 적용.
5. 버튼/입력/카드 라운드·섀도를 §2.3, §3 규격으로.

[하지 말 것]
- 위젯 구조, 상태 관리, API/네비게이션 로직 변경 금지.
- 새 색을 임의로 만들지 말 것(정책 토큰만 사용).

[산출물] 변경 diff + 사용한 토큰 목록.
```

### 5.3 예시 (커뮤니티)

```
[작업] 커뮤니티 화면을 C 방향으로 리스타일링.
- 소스: lib/screens/community_screen.dart
- 기준: 커뮤니티 화면 개선.dc.html
1) 카테고리 아이콘 타일 색을 #4A90E2 → #0284C7, 배경 #E8F2FC → #E0F2FE.
2) 각 행에 게시글 수 카운트 칩(#E0F2FE/#0284C7) + chevron-right(#CBD5E1) 추가.
3) 행 사이 1px #F4F7FA 구분선.
4) 헤더 알림/내 글/찜 아이콘은 Lucide 라인.
- 상세(글 목록/게시글 상세/글쓰기/찜한 글/알림/내 글)는 목업의 상태 배지·섐네일·CTA 규격을 따른다.
- 동작·쿼리·라우팅은 유지.
```

## 6. 권장 적용 순서

1. **토큰 정리** — `color_style_new.dart`의 primary를 스카이로 재정의 (전역 파급).
2. **공통 컴포넌트** — 버튼/입력/리스트 행/배지/토글 위젯을 §3 규격으로 1회 정비.
3. **화면 적용** — 로그인 → 홈 → 주소록 → 교회소식 → 채팅 → 커뮤니티 → 마이페이지 순.
4. **신규 화면 구현** — 마이페이지, 첫 로그인 프로필 선택은 목업 기준 신규 작성.
5. **QA** — 목업 프레임과 1:1 대조, 최소 글자 크기·터치 영역(44px) 확인.
